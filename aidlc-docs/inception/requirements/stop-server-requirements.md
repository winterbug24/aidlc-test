# 요구사항 문서: 서버 종료용 실행 파일 (3차 워크플로)

1차(`requirements.md`)와 2차(`web-ui-requirements.md`)의 요구사항은 그대로 유효하다. 이 문서는 추가되는 요구사항만 다룬다.

## 1. 의도 분석 요약

| 항목 | 내용 |
|---|---|
| 사용자 요청 | "직접 명령어를 쓰지 말고, 종료 되는 배치도 하나 만들었으면좋겠어" |
| 요청 유형 | Enhancement (기존 실행 파일 묶음에 종료 기능 추가) |
| 범위 | Single Component (실행 로직 모듈에 명령 하나 추가, 배치 파일 하나 추가) |
| 복잡도 | Simple |
| 요구사항 깊이 | Minimal |
| 프로젝트 유형 | Brownfield. 리버스 엔지니어링 산출물은 2차 워크플로에서 갱신되어 최신이므로 다시 수행하지 않음 |

### 배경
2차 워크플로의 설계 질문에서 서버 종료 방식은 "실행 창을 닫거나 Ctrl+C"로 정했다(FD-Q4:A). 그 뒤 실제로 써 보니 실행 창이 없는 경우(다른 방법으로 띄운 서버, 창을 닫았는데 남은 서버)에는 WSL 명령을 직접 입력해야 했다. 이를 더블클릭 한 번으로 대신할 수단을 추가한다. 기존 방식(창 닫기, Ctrl+C)은 그대로 유지한다.

### 확인 질문을 만들지 않은 이유
요청의 목적과 결과물이 분명하다(더블클릭으로 서버 종료). 구현을 좌우하는 선택 사항은 아래 "제안하는 결정"에 근거와 함께 적었으며, 승인 단계에서 바꿀 수 있다.

## 2. 제안하는 결정

| 주제 | 제안 | 근거 |
|---|---|---|
| 파일 이름 | `todo-stop.bat` | 기존 `todo-start.bat`, `todo-copy-key.bat`과 같은 규칙 |
| 종료 대상 | 이 프로젝트 폴더에서 실행 중인 To-Do 서버 전부. 어떻게 띄웠는지(시작 파일, 직접 명령, 다른 포트)는 가리지 않음 | 사용자가 원하는 것은 "어떻게 띄웠든 끄기"다 |
| 대상 식별 방법 | 현재 사용자의 프로세스 중 `python -m todo_api.server`로 실행됐고 작업 폴더가 이 프로젝트인 것 | 다른 프로젝트나 다른 프로그램을 건드리지 않기 위해. API 키가 필요 없음 |
| 종료 방식 | 정상 종료 요청을 보내고 최대 5초 기다린 뒤, 남아 있으면 강제 종료 | 기존 실행 로직의 서버 정리 방식과 같음. DB는 WAL 모드라 중간에 끊겨도 일관성이 유지됨 |
| 확인 질문 | 묻지 않고 바로 종료 | 서버를 끄는 것은 되돌릴 수 있는 동작이다(다시 켜면 됨). 데이터는 지워지지 않는다 |
| 실행 중인 서버가 없을 때 | "실행 중인 서버가 없습니다"라고 알리고 정상 종료 | 오류가 아니다 |
| 바탕화면 바로 가기 | 다른 두 파일처럼 "To-Do 종료" 바로 가기를 만든다 | 앞선 요청에서 두 파일 모두 바로 가기를 요청하셨음 |

## 3. 기능 요구사항

### SFR-01 종료용 실행 파일
- Windows 탐색기에서 `todo-stop.bat`을 더블클릭하면 실행 중인 To-Do 서버가 꺼진다.
- 다른 두 실행 파일과 같은 방식으로 자기 위치에서 프로젝트 경로를 알아낸다. 프로젝트 폴더 밖에 복사해 실행하면 안내하고 끝낸다.

### SFR-02 종료 대상
- 이 프로젝트 폴더에서 실행 중인 To-Do 서버를 모두 끈다. 포트와 시작 방법을 가리지 않는다.
- 다른 프로그램, 다른 폴더의 프로세스, 다른 사용자의 프로세스는 건드리지 않는다.
- 시작 파일로 띄운 서버를 끄면 그 실행 창의 실행 로직도 함께 끝난다(서버가 끝나면 실행 로직이 끝나는 기존 동작).

### SFR-03 결과 안내
- 끈 서버가 있으면 몇 개를 껐는지 알린다.
- 실행 중인 서버가 없으면 그렇다고 알린다.
- 끄지 못한 서버가 있으면 그 사실과 직접 확인하는 방법을 알린다.
- 창이 바로 닫히지 않아 결과를 읽을 수 있다.

### 범위에 포함하지 않는 것
- 화면(웹)에서 서버를 끄는 버튼
- 서버 재시작 기능
- 기존 종료 방식(창 닫기, Ctrl+C)의 변경

## 4. 비기능 요구사항

| ID | 요구사항 | 관련 규칙 |
|---|---|---|
| SNFR-01 | 종료 기능은 API 키를 읽거나 쓰지 않는다. 키를 출력하지 않는다 | SECURITY-12 |
| SNFR-02 | 종료 대상 식별은 프로세스 이름의 일부 일치가 아니라 실행 인자와 작업 폴더의 정확한 일치로 한다 | SECURITY-15 (잘못된 대상을 끄지 않음) |
| SNFR-03 | 정상 종료를 먼저 시도해 진행 중인 요청과 DB 기록이 마무리되게 한다 | RESILIENCY-10 |
| SNFR-04 | 종료 후 서버가 실제로 끝났는지 확인하고 결과를 알린다 | RESILIENCY-06 |
| SNFR-05 | 대상 선택 로직은 프로세스 목록을 입력으로 받는 순수 함수로 두고 자동 테스트한다. 실제 서버 프로세스를 띄워 끄는 테스트도 둔다 | PBT-03 (불변 조건: 선택 결과는 항상 조건에 맞는 프로세스뿐) |
| SNFR-06 | 기존 테스트 298개는 변경 없이 통과한다 | 회귀 방지 |
| SNFR-07 | README의 "웹 화면" 절과 문제 해결 절, 수동 확인 절차에 종료 파일을 반영한다 | RESILIENCY-15 |
| SNFR-08 | 새 의존성을 추가하지 않는다 | SECURITY-10 |

## 5. 확장 규칙 준수 요약 (Requirements Analysis 단계)

확장 설정은 그대로 유지한다(보안 적용, 복원력 적용, 속성 기반 테스트 부분 적용). 이번 변경으로 판정이 달라지는 규칙은 없다.

| 확장 | 상태 | 비고 |
|---|---|---|
| Security Baseline | 차단 발견 없음 | SNFR-01, 02, 08. 새 엔드포인트, 새 데이터 저장소, 새 의존성 없음 |
| Resiliency Baseline | 차단 발견 없음 | SNFR-03, 04, 07. 복원력 확장의 사용자 결정 항목은 1차 답변 유지, 새로 물을 항목 없음 |
| Property-Based Testing (부분) | 차단 발견 없음 | SNFR-05. 대상 선택의 불변 조건을 Hypothesis로 검증 |

## 6. 핵심 요약
- `todo-stop.bat`을 추가한다. 더블클릭하면 이 프로젝트의 To-Do 서버를 모두 끄고 결과를 알린다.
- 대상은 실행 인자와 작업 폴더로 정확히 식별해 다른 프로세스를 건드리지 않는다.
- 실행 로직 모듈에 종료 명령을 추가하고, 배치 파일은 그것을 부르기만 한다.
- 바탕화면에 "To-Do 종료" 바로 가기를 만든다.

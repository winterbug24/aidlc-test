# 요구사항 문서: 화면 주소 변경 (6차 워크플로)

## 1. 의도 분석 요약
| 항목 | 내용 |
|---|---|
| 사용자 요청 | "이거 url 명좀 바꾸자 http://127.0.0.1:8000/api_test  -> http://127.0.0.1:8000/todo_list  이걸로 변경하고 간단테스트 및 진행" |
| 요청 유형 | Enhancement (화면 경로 이름 변경) |
| 범위 | Single Component (화면 경로 정의, 실행 로직의 주소, 화면 문서의 파일 경로) |
| 복잡도 | Trivial |
| 요구사항 깊이 | Minimal. 확인 질문 없음 |

## 2. 기능 요구사항
- **UFR-01**: 화면을 `/todo_list`에서 제공한다. 스타일과 스크립트는 `/todo_list/app.css`, `/todo_list/app.js`.
- **UFR-02**: `todo-start.bat`(실행 로직)이 여는 주소와 창에 표시하는 주소를 `http://127.0.0.1:<포트>/todo_list`로 바꾼다.
- **UFR-03**: 옛 주소 `/api_test`는 제공하지 않는다(404). 사용자가 주소 "변경"을 요청했으므로 옛 주소를 남기거나 넘겨주지 않는다.

## 3. 비기능 요구사항
- **UNFR-01**: 경로만 바뀌고 동작(인증 없음, 고정 파일 목록만 제공, 보안 헤더, 요청 제한)은 그대로다 (SECURITY-04, 08, 11).
- **UNFR-02**: 화면과 API는 같은 출처(`http://127.0.0.1:8000`)라서 브라우저에 저장된 키는 그대로 쓰인다.
- **UNFR-03**: 테스트는 사용자 지시에 따라 관련 테스트만 실행한다.

## 4. 문서 범위
현재 상태를 설명하는 문서(README, 리버스 엔지니어링 문서, 빌드·보안·E2E 지침)는 새 주소로 고친다. 지난 워크플로의 요구사항, 계획, 설계 문서와 감사 로그는 당시 기록이므로 고치지 않는다.

## 5. 확장 규칙 준수
Security, Resiliency: 차단 발견 없음(경로 이름 외 변경 없음). PBT: N/A(속성 대상 없음).

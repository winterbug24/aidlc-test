# 요구사항 문서: 프로젝트를 D 드라이브로 이전 (5차 워크플로)

1~4차의 요구사항은 그대로 유효하다. 이 문서는 이전에 필요한 것만 다룬다.

| 항목 | 내용 |
|---|---|
| 사용자 요청 | "D:\workspace\to_do  이 경로로 이동 시켜주고, 바탕화면에 바로가기 해주고, 정상작동 여부 테스트까지 끝내주고 기존 이 폴더 파일은 삭제 진행해줘" |
| 요청 유형 | Migration(프로젝트 위치 이전) + Enhancement(배치 파일이 드라이브 경로도 인식) |
| 범위 | 배치 파일 3개, README, 환경 작업(복사, 가상 환경, 바로 가기, 기존 폴더 삭제) |
| 복잡도 | Simple~Moderate. 코드 변경은 작지만 되돌릴 수 없는 기존 폴더 삭제가 포함됨 |
| 요구사항 깊이 | Minimal (요청이 구체적이어서 확인 질문 없이 결정 사항을 아래에 기록) |

### 이전 전 확인 결과 (4차 워크플로 뒤 문의에서 확인)
- 배치 파일의 위치 판별(`:locate`)은 `\\wsl.localhost\` 또는 `\\wsl$\` 경로만 허용한다. `D:\...`에서 실행하면 안내 후 끝난다.
- `.venv`의 실행 파일에 옛 절대 경로가 들어 있어 그대로 옮기면 동작하지 않는다.
- `/mnt/d`는 권한 정보(metadata) 없이 연결되어 있어 0600으로 만든 파일이 0777로 보인다. SQLite(WAL)와 동시 쓰기는 정상이었다.
- 대상 폴더 `D:\workspace\to_do`는 이미 있고 비어 있다.
- 바탕화면에 `To-Do 시작`, `To-Do 종료`, `To-Do 키 복사` 바로 가기가 옛 경로를 가리킨다.

## 2. 결정 사항

| 주제 | 결정 | 근거 |
|---|---|---|
| 옮길 것 | 저장소 전체(`.git` 포함)와 실행 데이터: `.env`(API 키), `instance/`(DB), `backups/`, `logs/` | "똑같이 작동"하려면 할 일 데이터와 키가 그대로여야 한다. 키가 같으면 브라우저에 저장된 키도 그대로 쓸 수 있다 |
| 옮기지 않을 것 | `.venv`, `__pycache__`, `.pytest_cache`, `.hypothesis`, `test-results` | 가상 환경은 새 위치에서 다시 만든다. 나머지는 다시 생기는 캐시다 |
| 데이터 일관성 | 서버를 끄고 백업 도구로 백업한 뒤 복사한다 | 실행 중 복사하면 WAL 파일 때문에 DB가 어긋날 수 있다 |
| 배치 파일 | WSL 네트워크 경로와 드라이브 경로(`D:\...` → `/mnt/d/...`)를 모두 인식한다. 드라이브 경로이면 기본 WSL 배포판을 쓴다 | 현재 기본 배포판이 Ubuntu 하나뿐이다. 기존 위치 방식도 계속 동작해야 한다 |
| 파일 보호 | `.env`, `instance`, `backups`, `logs`에 Windows 권한(ACL)을 걸어 현재 Windows 사용자와 SYSTEM만 접근하게 한다 | `/mnt/d`에서는 리눅스 권한(0600)이 적용되지 않는다. 지금까지의 "소유자만 읽기" 보호를 Windows 권한으로 유지한다. WSL은 같은 Windows 사용자로 접근하므로 동작에는 영향이 없다 |
| git | 새 위치의 저장소에만 `core.filemode=false`를 설정한다 | `/mnt/d`에서는 모든 파일이 실행 권한이 있는 것으로 보여 변경으로 잡히기 때문이다 |
| 바로 가기 | 같은 이름의 바로 가기 3개를 새 경로로 다시 만든다(덮어씀) | 기존 바로 가기는 이전 작업에서 만든 것이고 옛 경로를 가리킨다 |
| 기존 폴더 삭제 | 새 위치에서 테스트, 서버 시작, 배치 파일 실행, 데이터 일치를 모두 확인한 뒤에만 `/home/winterbug/aidlc-test`를 삭제한다. 확인이 하나라도 실패하면 삭제하지 않고 보고한다 | 되돌릴 수 없는 작업이다. git 기록, 데이터, 키가 모두 새 위치에 있음을 먼저 확인한다 |

## 3. 기능 요구사항

### RFR-01 배치 파일의 드라이브 경로 지원
- `todo-start.bat`, `todo-stop.bat`, `todo-copy-key.bat`을 `D:\workspace\to_do`에서 실행하면 `/mnt/d/workspace/to_do`에서 동작한다.
- WSL 네트워크 경로에서 실행하는 기존 방식도 그대로 동작한다.
- 그 밖의 위치(예: 바탕화면에 파일을 복사한 경우)에서는 기존처럼 바로 가기를 쓰라고 안내한다. 판별 기준은 "이 파일과 같은 폴더에 `src\todo_api`가 있는가"로 바꾼다.

### RFR-02 이전
- 위 2장의 대상이 새 위치에 같은 내용으로 있다(git 커밋, `.env` 내용, DB 행).
- 새 위치에 `.venv`를 만들고 실행 의존성과 개발 의존성을 설치한다.

### RFR-03 바탕화면 바로 가기
- `To-Do 시작`, `To-Do 종료`, `To-Do 키 복사`가 새 위치의 배치 파일을 가리킨다.

### RFR-04 정상 작동 확인
- 새 위치에서 자동 테스트 전체가 통과한다.
- 배치 파일 3개를 Windows 명령 해석기로 실제 실행해 확인한다(시작, 키 복사, 종료).
- 이전 후 서버를 새 위치에서 띄워 둔다.

### RFR-05 기존 폴더 삭제
- RFR-02~04가 모두 확인되면 `/home/winterbug/aidlc-test`를 삭제한다.

# 페르소나 (2차 워크플로: 웹 화면 추가)

사용자 유형은 하나다 (스토리 계획 질문 1:A).

## P-01 개발자 본인

| 항목 | 내용 |
|---|---|
| 역할 | 이 프로젝트를 직접 만들고 운영하는 개발자이자 유일한 사용자 |
| 기술 수준 | WSL, 터미널, 환경 변수, API 키 개념을 안다. curl로 API를 호출할 수 있다 |
| 사용 환경 | Windows PC 한 대. 서버는 WSL(Ubuntu)에서 실행하고 화면은 Windows의 Edge 또는 Chrome에서 본다 |
| 사용 방식 | 하루에 몇 번 화면을 열어 할 일을 적고 체크한다. 다른 사람과 공유하지 않는다 |

### 목표
- 터미널을 열지 않고 더블클릭 한 번으로 할 일 화면을 띄운다
- 할 일을 빠르게 적고, 끝난 일을 체크하고, 필요 없는 것을 지운다
- 키를 매번 입력하지 않는다

### 불편한 점 (지금)
- 화면이 없어 curl이나 PowerShell 명령을 직접 쳐야 한다
- 헤더에 키를 매번 넣어야 한다
- 서버를 띄우려면 WSL 터미널에서 환경 변수를 불러오고 명령을 입력해야 한다

### 기대하는 화면
- 한눈에 들어오는 단순한 한 페이지
- Windows의 밝게/어둡게 설정과 어울리는 모습
- 문제가 생기면 무엇이 잘못됐고 어떻게 하면 되는지 알려 주는 안내

### 이 페르소나에 맞춘 결정
- 안내 문구에 "API 키", "서버", "포트" 같은 용어를 그대로 쓴다. 풀어 쓰는 도움말은 넣지 않는다
- 문제 상황에서는 원인과 조치를 짧게 알려 주고, 자세한 절차는 README를 참고하게 한다

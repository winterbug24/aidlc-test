# 사용자 스토리 (2차 워크플로: 웹 화면 추가)

- **분해 방식**: 사용자 여정 기반 (여정 4개, 스토리 18개)
- **주체**: 모든 스토리의 "나"는 페르소나 P-01(개발자 본인)이다
- **수용 기준 형식**: Given(조건) / When(동작) / Then(기대 결과)
- **기준 문서**: `aidlc-docs/inception/requirements/web-ui-requirements.md`

용어: "화면"은 `/api_test`의 할 일 관리 화면, "실행 파일"은 Windows 배치 파일, "저장된 키"는 브라우저에 저장된 API 키를 뜻한다.

---

## 여정 1. 처음 시작하기

### US-01 실행 파일로 서버와 화면 열기
나는 터미널을 열지 않고 할 일 화면을 쓰고 싶으므로, 실행 파일을 더블클릭하면 서버가 뜨고 브라우저에 화면이 열리기를 원한다.

**관련 요구사항**: WFR-11, WNFR-RES-03, WNFR-SEC-06, WNFR-SEC-11

**수용 기준**
- AC-01.1
  - Given 서버가 실행 중이 아니고 8000번 포트가 비어 있다
  - When 실행 파일을 더블클릭한다
  - Then WSL에서 서버가 시작되고, 서버가 응답하기 시작한 뒤에 기본 브라우저로 `http://127.0.0.1:8000/api_test`가 열린다
- AC-01.2
  - Given 서버가 시작됐다
  - When 실행 창을 본다
  - Then 화면 주소와 서버를 끄는 방법이 표시되어 있다
- AC-01.3
  - Given API 키가 아직 만들어지지 않았다
  - When 실행 파일을 실행한다
  - Then 새 키가 만들어져 소유자만 읽을 수 있는 파일에 저장되고, 키가 클립보드에 복사되며, 실행 창에 "화면에 붙여넣으세요"라는 안내가 나온다. 실행 창에는 키 값이 표시되지 않는다
- AC-01.4
  - Given 서버가 정해진 시간 안에 응답하지 않는다
  - When 실행 파일이 기다리는 시간이 끝난다
  - Then 브라우저를 열지 않고 실패했다는 사실과 확인할 곳(로그 위치 등)을 실행 창에 알린다

### US-02 이미 실행 중일 때 화면만 열기
나는 서버를 켜 둔 것을 잊고 실행 파일을 다시 누를 수 있으므로, 그럴 때 서버가 또 뜨지 않고 화면만 열리기를 원한다.

**관련 요구사항**: WFR-11

**수용 기준**
- AC-02.1
  - Given 이 To-Do 서버가 이미 실행 중이다
  - When 실행 파일을 더블클릭한다
  - Then 새 서버를 시작하지 않고, 실행 중인 서버의 화면 주소가 브라우저에 열린다
- AC-02.2
  - Given 위 상황이다
  - When 실행 창을 본다
  - Then 이미 실행 중인 서버를 사용한다는 안내가 나온다

### US-03 포트가 사용 중일 때 빈 포트로 열기
나는 8000번 포트를 다른 프로그램이 쓰고 있어도 화면을 쓰고 싶으므로, 실행 파일이 빈 포트를 알아서 찾아 주기를 원한다.

**관련 요구사항**: WFR-11

**수용 기준**
- AC-03.1
  - Given 8000번 포트를 이 To-Do 서버가 아닌 다른 프로그램이 쓰고 있다
  - When 실행 파일을 더블클릭한다
  - Then 8001번부터 차례로 빈 포트를 찾아 그 포트로 서버를 시작하고, 같은 포트의 화면 주소를 브라우저에 연다
- AC-03.2
  - Given 8000번이 아닌 포트로 서버가 시작됐다
  - When 실행 창을 본다
  - Then 실제 사용 중인 주소가 표시되고, 이 주소에서는 키를 다시 입력해야 할 수 있다는 안내가 나온다
- AC-03.3
  - Given 정해진 범위 안에서 빈 포트를 찾지 못했다
  - When 실행 파일이 탐색을 마친다
  - Then 서버를 시작하지 않고 그 사실을 알린다

### US-04 키를 다시 복사하기와 서버 끄기
나는 다른 포트나 다른 브라우저에서 키를 다시 입력해야 할 때가 있으므로, 키를 다시 클립보드로 가져오는 방법과 서버를 끄는 분명한 방법을 원한다.

**관련 요구사항**: WFR-11, WNFR-SEC-06

**수용 기준**
- AC-04.1
  - Given API 키가 이미 만들어져 있다
  - When 제공된 방법으로 키 복사를 실행한다
  - Then 키가 클립보드에 복사되고 키 값은 창에 표시되지 않는다
- AC-04.2
  - Given 실행 파일로 서버를 시작했다
  - When 실행 창에 안내된 방법으로 종료한다
  - Then 서버가 멈추고 화면 주소가 더 이상 열리지 않는다

## 여정 2. 키 입력하기

### US-05 키를 입력해 들어가기
나는 내 할 일을 다른 프로그램이 함부로 읽지 못하게 하고 싶으므로, 화면에서 API 키를 입력한 뒤에만 할 일이 보이기를 원한다.

**관련 요구사항**: WFR-01, WFR-02, WNFR-SEC-04, WNFR-SEC-05

**수용 기준**
- AC-05.1
  - Given 브라우저에 저장된 키가 없다
  - When 화면 주소를 연다
  - Then 키 입력 화면이 보이고 할 일 목록은 보이지 않는다
- AC-05.2
  - Given 키 입력 화면이다
  - When 키를 입력한다
  - Then 입력한 글자가 가려져 보인다
- AC-05.3
  - Given 키 입력 화면이다
  - When 올바른 키를 입력하고 확인을 누르거나 Enter를 누른다
  - Then 할 일 목록 화면으로 넘어가고 키가 브라우저에 저장된다
- AC-05.4
  - Given 키를 입력해 들어갔다
  - When 브라우저의 주소 표시줄을 본다
  - Then 주소에 키가 들어 있지 않다

### US-06 다음 방문 때 바로 들어가기
나는 키를 매번 입력하고 싶지 않으므로, 한 번 입력한 뒤에는 화면을 열면 바로 목록이 보이기를 원한다.

**관련 요구사항**: WFR-02

**수용 기준**
- AC-06.1
  - Given 같은 주소(포트 포함)에서 올바른 키를 입력한 적이 있다
  - When 브라우저를 닫았다가 다시 화면 주소를 연다
  - Then 키 입력 없이 할 일 목록이 바로 보인다

### US-07 키 지우기
나는 이 브라우저에 키를 남겨 두고 싶지 않을 때가 있으므로, 저장된 키를 지우는 기능을 원한다.

**관련 요구사항**: WFR-02

**수용 기준**
- AC-07.1
  - Given 할 일 목록 화면이다
  - When "키 지우기"를 누른다
  - Then 저장된 키가 지워지고 키 입력 화면으로 돌아가며, 할 일 목록은 더 이상 보이지 않는다
- AC-07.2
  - Given 키를 지웠다
  - When 화면 주소를 다시 연다
  - Then 키 입력 화면이 보인다

## 여정 3. 할 일 관리하기

### US-08 목록 보기
나는 해야 할 일을 한눈에 보고 싶으므로, 화면에 할 일이 최신 순으로 정리되어 보이기를 원한다.

**관련 요구사항**: WFR-03, WFR-09, WNFR-SEC-03, WNFR-PERF-01

**수용 기준**
- AC-08.1
  - Given 할 일이 여러 개 있다
  - When 목록 화면이 열린다
  - Then 삭제되지 않은 할 일이 최근에 만든 것부터 순서대로 보인다
- AC-08.2
  - Given 완료된 할 일과 미완료 할 일이 섞여 있다
  - When 목록을 본다
  - Then 완료된 항목은 체크되어 있고 미완료 항목과 다르게 표시된다
- AC-08.3
  - Given 할 일이 하나도 없다
  - When 목록 화면이 열린다
  - Then 할 일이 없다는 안내가 보인다
- AC-08.4
  - Given 제목이 `<b>굵게</b> a < b`인 할 일이 있다
  - When 목록을 본다
  - Then 제목이 글자 그대로 `<b>굵게</b> a < b`로 보이고 굵은 글씨나 다른 서식으로 바뀌지 않는다
- AC-08.5
  - Given 제목이 200자인 할 일이 있다
  - When 목록을 본다
  - Then 제목 전체가 줄바꿈되어 보이고 화면이 옆으로 넘치지 않는다
- AC-08.6
  - Given 목록을 불러오는 중이다
  - When 화면을 본다
  - Then 불러오는 중이라는 표시가 보인다

### US-09 할 일 추가하기
나는 떠오른 일을 바로 적고 싶으므로, 제목을 입력하고 Enter만 누르면 추가되기를 원한다.

**관련 요구사항**: WFR-04

**수용 기준**
- AC-09.1
  - Given 목록 화면이다
  - When 제목을 입력하고 Enter를 누르거나 추가 버튼을 누른다
  - Then 새 할 일이 목록 맨 위에 미완료 상태로 나타나고 입력 칸이 비워진다
- AC-09.2
  - Given 앞뒤에 공백이 있는 제목을 입력했다
  - When 추가한다
  - Then 앞뒤 공백이 제거된 제목으로 목록에 나타난다
- AC-09.3
  - Given 입력 칸이 비어 있거나 공백만 있다
  - When 추가를 시도한다
  - Then 서버에 요청을 보내지 않고 제목을 입력하라고 알린다
- AC-09.4
  - Given 입력 칸이다
  - When 200자를 넘겨 입력하려 한다
  - Then 200자까지만 입력된다

### US-10 완료 체크와 해제
나는 끝낸 일을 표시하고 싶고 잘못 체크하면 되돌리고 싶으므로, 체크 표시를 눌러 완료와 미완료를 오가기를 원한다.

**관련 요구사항**: WFR-05

**수용 기준**
- AC-10.1
  - Given 미완료 할 일이 있다
  - When 그 항목의 체크 표시를 누른다
  - Then 완료로 표시되고, 화면을 새로 열어도 완료 상태다
- AC-10.2
  - Given 완료된 할 일이 있다
  - When 그 항목의 체크 표시를 누른다
  - Then 미완료로 돌아가고, 화면을 새로 열어도 미완료 상태다
- AC-10.3
  - Given 서버가 변경 요청을 거부한다
  - When 체크 표시를 누른다
  - Then 체크 표시가 원래 상태로 돌아가고 오류 안내가 보인다

### US-11 삭제하기
나는 필요 없는 일을 지우고 싶지만 실수로 지우고 싶지는 않으므로, 삭제 전에 한 번 확인받기를 원한다.

**관련 요구사항**: WFR-06

**수용 기준**
- AC-11.1
  - Given 할 일이 있다
  - When 그 항목의 삭제 버튼을 누른다
  - Then 되돌릴 수 없다는 내용이 담긴 확인 요청이 나오고, 아직 삭제되지 않는다
- AC-11.2
  - Given 삭제 확인 요청이 나와 있다
  - When 삭제를 확인한다
  - Then 그 항목이 목록에서 사라지고, 화면을 새로 열어도 나타나지 않는다
- AC-11.3
  - Given 삭제 확인 요청이 나와 있다
  - When 취소한다
  - Then 그 항목이 목록에 그대로 남는다

### US-12 필터로 골라 보기
나는 남은 일만 보거나 끝낸 일만 보고 싶을 때가 있으므로, 전체, 미완료, 완료를 골라 보기를 원한다.

**관련 요구사항**: WFR-07

**수용 기준**
- AC-12.1
  - Given 목록 화면을 처음 열었다
  - When 필터를 본다
  - Then "전체"가 선택되어 있다
- AC-12.2
  - Given 완료와 미완료 할 일이 섞여 있다
  - When "미완료"를 고른다
  - Then 미완료 항목만 보이고 "미완료"가 선택된 것으로 표시된다
- AC-12.3
  - Given 위와 같다
  - When "완료"를 고른다
  - Then 완료 항목만 보인다
- AC-12.4
  - Given "미완료" 필터가 선택되어 있다
  - When 어떤 항목을 완료로 체크한다
  - Then 그 항목이 목록에서 사라진다
- AC-12.5
  - Given 고른 필터에 해당하는 항목이 없다
  - When 목록을 본다
  - Then 해당하는 할 일이 없다는 안내가 보인다

### US-13 새로고침
나는 curl 같은 다른 도구로 바꾼 내용을 화면에서도 보고 싶으므로, 버튼으로 목록을 다시 불러오기를 원한다.

**관련 요구사항**: WFR-08, WNFR-PERF-02

**수용 기준**
- AC-13.1
  - Given 화면 밖에서 할 일이 추가됐다
  - When 새로고침 버튼을 누른다
  - Then 추가된 할 일이 목록에 나타나고, 선택해 둔 필터는 그대로 유지된다
- AC-13.2
  - Given 목록 화면을 열어 둔 채 아무것도 하지 않는다
  - When 시간이 지난다
  - Then 화면이 서버에 요청을 보내지 않는다

### US-14 Windows에서 깔끔하게 보이기
나는 Windows에서 이 화면을 쓰므로, 내 Windows 설정과 어울리고 창 크기를 바꿔도 깨지지 않기를 원한다.

**관련 요구사항**: WFR-10, WNFR-UX-01~05

**수용 기준**
- AC-14.1
  - Given Windows 앱 모드가 "어둡게"다
  - When 화면을 연다
  - Then 어두운 배경과 밝은 글자의 테마로 보인다
- AC-14.2
  - Given Windows 앱 모드가 "밝게"다
  - When 화면을 연다
  - Then 밝은 배경과 어두운 글자의 테마로 보인다
- AC-14.3
  - Given 화면이 열려 있다
  - When 창 너비를 약 480px까지 줄인다
  - Then 내용이 잘리거나 겹치지 않고 가로 스크롤이 생기지 않는다
- AC-14.4
  - Given 화면이 열려 있다
  - When 마우스 없이 Tab, Enter, Space 키만 사용한다
  - Then 키 입력, 추가, 체크, 삭제, 필터, 새로고침, 키 지우기를 모두 할 수 있고 현재 포커스 위치가 보인다
- AC-14.5
  - Given Edge와 Chrome에서 같은 화면을 연다
  - When 두 화면을 비교한다
  - Then 배치와 동작이 같다

## 여정 4. 문제 상황 대처하기

### US-15 잘못된 키와 바뀐 키
나는 키를 잘못 붙여넣거나 서버의 키를 바꿀 수 있으므로, 그럴 때 무엇이 문제인지 알고 다시 입력할 수 있기를 원한다.

**관련 요구사항**: WFR-02, WFR-09

**수용 기준**
- AC-15.1
  - Given 키 입력 화면이다
  - When 틀린 키를 입력하고 확인한다
  - Then 키가 올바르지 않다는 안내가 보이고, 키는 저장되지 않으며, 키 입력 화면에 머문다
- AC-15.2
  - Given 저장된 키가 있는데 서버의 키가 바뀌었다
  - When 화면을 열거나 목록 화면에서 어떤 동작을 한다
  - Then 저장된 키가 지워지고 키를 다시 입력하라는 안내와 함께 키 입력 화면이 보인다

### US-16 입력 오류 안내
나는 같은 일을 두 번 적는 실수를 할 수 있으므로, 추가가 거부되면 이유를 알고 입력한 내용을 고칠 수 있기를 원한다.

**관련 요구사항**: WFR-04, WFR-09

**수용 기준**
- AC-16.1
  - Given "우유 사기"라는 할 일이 이미 있다
  - When "우유 사기"를 다시 추가한다
  - Then 같은 제목이 이미 있다는 서버의 안내 문구가 화면에 보이고, 입력 칸의 내용은 지워지지 않으며, 목록은 바뀌지 않는다
- AC-16.2
  - Given 서버가 입력을 거부했다 (예: 제목에 허용되지 않는 문자)
  - When 응답이 온다
  - Then 서버가 보낸 안내 문구가 화면에 보이고 입력 칸의 내용은 지워지지 않는다
- AC-16.3
  - Given 오류 안내가 보이고 있다
  - When 다음 동작이 성공한다
  - Then 이전 오류 안내가 사라진다

### US-17 요청 제한 안내
나는 화면을 빠르게 여러 번 조작하거나 키를 여러 번 틀릴 수 있으므로, 제한에 걸리면 기다리면 된다는 것을 알기를 원한다.

**관련 요구사항**: WFR-09, WNFR-SEC-08

**수용 기준**
- AC-17.1
  - Given 요청 제한에 걸렸다 (서버가 429를 응답한다)
  - When 목록 화면에서 어떤 동작을 한다
  - Then 요청이 너무 많으니 잠시 후 다시 시도하라는 안내가 보이고, 화면의 기존 목록은 그대로 남는다
- AC-17.2
  - Given 키를 여러 번 틀려 인증 실패 한도에 걸렸다
  - When 키 입력 화면에서 올바른 키를 입력한다
  - Then 잠시 후 다시 시도하라는 안내가 보이고 키 입력 화면에 머문다. 키가 틀렸다는 안내와 구분된다

### US-18 서버에 연결할 수 없을 때
나는 서버를 끈 채로 화면을 열 수도 있으므로, 화면이 멈추지 않고 서버 상태를 확인하라고 알려 주기를 원한다.

**관련 요구사항**: WFR-09, WNFR-RES-01, WNFR-RES-02

**수용 기준**
- AC-18.1
  - Given 목록 화면이 열려 있는데 서버가 꺼졌다
  - When 어떤 동작을 한다
  - Then 서버에 연결할 수 없다는 안내와 다시 시도하는 방법이 보이고, 화면의 기존 목록은 그대로 남는다
- AC-18.2
  - Given 서버가 응답하지 않는다
  - When 정해진 제한 시간이 지난다
  - Then 요청을 실패로 처리하고 위와 같은 안내를 보여 준다. 불러오는 중 표시가 계속 남아 있지 않는다
- AC-18.3
  - Given 서버가 DB를 쓸 수 없다고 응답한다 (503)
  - When 응답이 온다
  - Then 서버의 안내 문구가 보이고 다시 시도할 수 있다
- AC-18.4
  - Given 연결 실패 안내가 보이고 있다
  - When 서버가 다시 켜진 뒤 다시 시도한다
  - Then 목록이 정상적으로 보이고 안내가 사라진다

## INVEST 점검

| 기준 | 점검 결과 |
|---|---|
| Independent (독립적) | 여정 2~4의 스토리는 화면이 열려 있다는 전제만 공유하고 서로의 완료를 요구하지 않는다. 여정 1(실행 파일)은 화면 스토리와 독립적으로 구현하고 검증할 수 있다 |
| Negotiable (협상 가능) | 배치, 문구, 확인 방식(대화상자 형태) 등 구현 방법은 수용 기준에 고정하지 않았다 |
| Valuable (가치 있음) | 스토리마다 사용자가 얻는 것을 서술문에 밝혔다 |
| Estimable (추정 가능) | 각 스토리는 화면 요소 한두 개와 API 호출 한두 개 범위다 |
| Small (작음) | 스토리 하나는 사용자 동작 하나 또는 문제 상황 하나다. 가장 큰 US-01도 실행 파일 하나의 범위다 |
| Testable (테스트 가능) | 모든 수용 기준이 관찰 가능한 결과로 끝난다. 여정 2~4는 브라우저 자동화 테스트로, 여정 1과 US-14의 일부(화면 배율, 두 브라우저 비교)는 수동 확인으로 검증한다 |

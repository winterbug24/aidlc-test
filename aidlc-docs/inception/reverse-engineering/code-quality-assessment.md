# 코드 품질 평가

## 테스트 커버리지
- **전체**: Good (수치는 측정하지 않음. 커버리지 도구 미포함)
- **단위 테스트**: 검증, 직렬화, 설정, 저장소 55개
- **통합 테스트**: API 85개, 복원력 12개, 속성 기반 9개 (상태 기반 모델 테스트 포함)
- **실행 결과**: 161개 통과 (로컬과 GitHub Actions 모두)
- **프런트엔드 테스트**: 없음 (화면이 없음)

## 코드 품질 지표
- **린트**: 구성되지 않음
- **코드 스타일**: 일관됨 (타입 힌트, 모듈별 책임 분리, 한국어 주석)
- **문서**: Good (README, 요구사항/설계 문서, 빌드·테스트 지침)

## 기술 부채와 제약

| 항목 | 위치 | 설명 |
|---|---|---|
| 패키지 미설치 실행 | 전체 | `PYTHONPATH=src`가 필요하다. 설치형 패키지나 실행 스크립트가 없다 |
| 단일 프로세스 전제 | `rate_limit.py` | 요청 제한 카운터가 메모리에 있다 |
| 페이지네이션 없음 | `routes/todos.py` | 항목이 매우 많아지면 목록 응답이 커진다 (수용한 위험) |
| 마이그레이션 도구 없음 | `db.py` | 스키마는 "없으면 생성"과, 4차 워크플로에서 추가한 열 추가 함수(`migrate`)뿐이다. 버전 번호 관리는 없으므로 열 추가 외의 스키마 변경에는 별도 절차가 필요하다 |
| 린트/포맷 도구 없음 | - | CI에 정적 검사가 없다 |
| 커버리지 미측정 | - | 수치 근거가 없다 |

## 웹 화면 추가와 관련된 현재 상태

| 항목 | 위치 | 영향 |
|---|---|---|
| CORS 미허용 | 전체 | 다른 출처(다른 포트, 파일로 연 HTML)의 페이지는 API를 호출할 수 없다. 화면은 같은 서버가 제공해야 한다 |
| 정적 파일/HTML 제공 없음 | `app.py` | 화면을 제공하는 라우트가 없다 |
| 헤더 기반 인증만 지원 | `auth.py` | 브라우저 주소창으로는 `/todos`를 열 수 없다. 화면의 스크립트가 `X-API-Key`를 보내야 하며, 키를 브라우저에서 어떻게 입력받고 보관할지 정해야 한다 |
| 모든 응답 `Cache-Control: no-store` | `logging_setup.py` | 정적 파일에도 적용된다. 로컬에서는 문제없지만 화면 파일에 맞게 조정할지 검토 대상 |
| HTML 보안 헤더 없음 | `logging_setup.py` | 지금까지 HTML을 제공하지 않아 SECURITY-04(CSP 등)가 N/A였다. HTML을 제공하면 적용 대상이 된다 |
| 제목 원문 저장 | `validation.py` | `<`, `>`가 그대로 저장된다. 화면은 제목을 반드시 텍스트로 넣어야 한다 (HTML로 넣으면 XSS) |
| 인증 실패 한도 | `rate_limit.py` | 화면에서 잘못된 키를 반복 입력하면 최대 1분간 잠긴다. 화면이 429를 안내해야 한다 |
| 전체 요청 한도 분당 60회 | `rate_limit.py` | 화면의 자동 새로고침 주기를 정할 때 고려해야 한다 |

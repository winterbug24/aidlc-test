# 도메인 엔티티 - todo-api

## 1. 개요
도메인 엔티티는 `Todo` 하나다. 다른 엔티티와의 관계는 없다(사용자 계정 없음, 단일 API 키).

## 2. Todo 엔티티

| 필드 | 타입 | 필수 | 설정 주체 | 제약 | API 응답 노출 |
|---|---|---|---|---|---|
| id | 양의 정수 | 예 | 서버 (자동 증가) | 1 이상, 재사용하지 않음 | 예 |
| title | 문자열 | 예 | 클라이언트 | 정규화 후 1~200자, 제어 문자 불가 (BR-01 참조) | 예 |
| completed | 불리언 | 예 | 서버 기본값 false, 이후 클라이언트가 변경 | true 또는 false | 예 |
| created_at | 시각 (UTC) | 예 | 서버 | 생성 시 1회 기록, 이후 불변 | 예 (ISO 8601, `Z` 접미사) |
| deleted_at | 시각 (UTC) 또는 없음 | 아니오 | 서버 | 논리 삭제 시 1회 기록, 이후 불변 | 아니오 |

### 파생 개념
- **활성(active) 항목**: `deleted_at`이 없는 항목. API로 보이는 것은 활성 항목뿐이다.
- **삭제된 항목**: `deleted_at`이 있는 항목. 저장소에는 남아 있지만 모든 API 동작에서 존재하지 않는 것으로 취급한다.

## 3. 상태 모델

```text
  POST /todos
       |
       v
+-------------+  completed=true   +-------------+
|   PENDING   | ----------------> |  COMPLETED  |
|   (active)  | <---------------- |   (active)  |
+-------------+  completed=false  +-------------+
       |                                 |
       | DELETE                          | DELETE
       v                                 v
+-----------------------------------------------+
|              DELETED (terminal)               |
+-----------------------------------------------+
```

### 텍스트 설명
- 그림의 PENDING은 "미완료", COMPLETED는 "완료", DELETED는 "삭제됨" 상태다.
- 생성 직후 상태는 "미완료"다.
- "미완료"와 "완료"는 서로 자유롭게 전환된다. 같은 상태로의 변경 요청은 상태를 바꾸지 않고 성공한다.
- 두 활성 상태 모두 "삭제됨"으로 전환될 수 있다.
- "삭제됨"은 종료 상태다. 복구도, 추가 변경도 없다.

## 4. 불변 조건 (Invariants)

| ID | 불변 조건 |
|---|---|
| INV-01 | 활성 항목들의 제목은 영문 대소문자를 무시하고 비교했을 때 서로 모두 다르다 |
| INV-02 | 모든 항목의 제목은 정규화된 상태(앞뒤 공백 없음, 1~200자, 제어 문자 없음)로 저장된다 |
| INV-03 | `id`와 `created_at`은 생성 후 변하지 않는다 |
| INV-04 | `deleted_at`은 한 번 기록되면 변하지 않는다 |
| INV-05 | 삭제된 항목은 어떤 조회 결과에도 포함되지 않는다 |
| INV-06 | 삭제된 항목의 제목은 중복 판정 대상이 아니다 (같은 제목을 다시 등록할 수 있다) |

## 5. API 표현

### Todo 표현 (JSON)
| 키 | 타입 | 예시 |
|---|---|---|
| `id` | 숫자 | `1` |
| `title` | 문자열 | `"우유 사기"` |
| `completed` | 불리언 | `false` |
| `created_at` | 문자열 | `"2026-10-12T05:00:00Z"` |

`deleted_at`은 표현에 포함하지 않는다.

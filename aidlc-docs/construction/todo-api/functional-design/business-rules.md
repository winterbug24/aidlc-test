# 업무 규칙 - todo-api

근거 표기: FR/NFR은 요구사항 문서, FD-Q는 Functional Design 질문, FD-CQ는 추가 확인 질문을 가리킨다.

## 1. 제목 규칙

| ID | 규칙 | 위반 시 | 근거 |
|---|---|---|---|
| BR-01 | 제목은 문자열이어야 한다 (숫자, 불리언, null, 배열, 객체는 불가) | 400 `validation_error` | FR-01 |
| BR-02 | 제목은 앞뒤 공백을 제거한 값으로 정규화하여 저장하고 반환한다. 그 외의 변환(이스케이프, 대소문자 변경 등)은 하지 않는다 | - | FR-01, FD-Q3:C |
| BR-03 | 정규화된 제목의 길이는 1자 이상 200자 이하다 (유니코드 코드 포인트 기준) | 400 `validation_error` | FR-01 |
| BR-04 | 정규화된 제목에 제어 문자(줄바꿈, 탭, NUL 등 유니코드 Cc 범주)가 있으면 거부한다. 저장할 수 없는 짝이 맞지 않는 서로게이트 문자(Cs 범주)도 함께 거부한다 (Code Generation 단계에서 추가) | 400 `validation_error` | FD-Q3:C |
| BR-05 | `<`, `>` 등 HTML로 해석될 수 있는 문자는 허용하며 원문 그대로 저장한다. 모든 응답은 JSON으로만 반환한다 | - | FD-Q3:C |
| BR-06 | 활성 항목 중 영문 대소문자를 무시했을 때 같은 제목이 있으면 생성을 거부한다. 완료된 항목도 비교 대상이다 | 409 `duplicate_title` | FD-Q1:B, FD-CQ2:B |
| BR-07 | 삭제된 항목의 제목은 중복 판정에서 제외한다 | - | FD-Q1:B |
| BR-08 | 중복 판정과 저장은 동시 요청에서도 INV-01이 깨지지 않도록 원자적으로 보장한다 | 409 `duplicate_title` | INV-01 |

대소문자 무시는 영문 A~Z에만 적용한다. 그 밖의 문자는 완전히 같을 때만 같은 문자로 본다.

## 2. 요청 형식 규칙

| ID | 규칙 | 위반 시 | 근거 |
|---|---|---|---|
| BR-10 | 본문이 있는 요청(추가, 완료 상태 변경)의 본문은 JSON 객체여야 한다 | 400 `validation_error` (JSON이 아닌 콘텐츠 타입은 415 `unsupported_media_type`) | NFR-SEC-04 |
| BR-11 | 본문에 정의되지 않은 필드가 있으면 요청을 거부하고, 오류 응답에 해당 필드 이름을 담는다 | 400 `validation_error` | FD-Q4, FD-CQ1:B |
| BR-12 | 필수 필드가 없으면 거부한다 (추가: `title`, 완료 상태 변경: `completed`) | 400 `validation_error` | FR-01, FR-04 |
| BR-13 | `completed`는 JSON 불리언이어야 한다 (`"true"`, `1`, `null` 등은 불가) | 400 `validation_error` | FR-04, NFR-SEC-04 |
| BR-14 | 목록 조회의 `completed` 쿼리 값은 `true` 또는 `false`만 허용한다 (소문자) | 400 `validation_error` | FR-02 |
| BR-15 | 목록 조회에서 정의되지 않은 쿼리 파라미터가 있으면 거부한다 | 400 `validation_error` | FD-CQ1:B와 일관 |
| BR-16 | 경로의 id는 양의 정수여야 한다. 그렇지 않은 경로는 존재하지 않는 자원으로 취급한다 | 404 `not_found` | NFR-SEC-04 |
| BR-17 | 요청 본문 크기에는 상한이 있다 (구체 값은 NFR 단계에서 확정) | 413 `payload_too_large` | NFR-SEC-04 |

## 3. 조회 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| BR-20 | 모든 조회는 활성 항목만 대상으로 한다 | FR-05, INV-05 |
| BR-21 | 목록은 최신 순으로 정렬한다 (`created_at` 내림차순, 같으면 `id` 내림차순) | FD-Q2:B |
| BR-22 | `completed` 필터가 있으면 해당 상태의 항목만 반환한다. 없으면 전체 활성 항목을 반환한다 | FR-02 |
| BR-23 | 결과가 없으면 빈 목록을 반환한다 (오류 아님) | FR-02 |
| BR-24 | 단건 조회 대상이 없거나 삭제된 항목이면 404를 반환한다 | FR-03 |

## 4. 완료 상태 변경 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| BR-30 | 활성 항목의 `completed`를 요청 값으로 설정한다 | FR-04 |
| BR-31 | 현재 값과 같은 값으로의 변경은 상태를 바꾸지 않고 성공하며 현재 표현을 반환한다 (멱등) | FR-04 |
| BR-32 | 변경 가능한 필드는 `completed`뿐이다. `title` 등 다른 필드는 BR-11에 따라 거부된다 | 범위 제외 항목 |
| BR-33 | 대상이 없거나 삭제된 항목이면 404를 반환한다 | FR-04 |

## 5. 삭제 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| BR-40 | 삭제는 활성 항목에 삭제 시각을 기록하는 논리 삭제다. 저장소의 행은 제거하지 않는다 | FR-05 |
| BR-41 | 대상이 없거나 이미 삭제된 항목이면 404를 반환한다 | FR-05 |
| BR-42 | 삭제된 항목은 조회, 변경, 재삭제 모두 불가하며 복구 기능은 없다 | FR-05 |
| BR-43 | 삭제 후에는 같은 제목을 다시 등록할 수 있다 | BR-07 |

## 6. 접근 규칙

| ID | 규칙 | 위반 시 | 근거 |
|---|---|---|---|
| BR-50 | `/todos` 하위의 모든 동작은 유효한 API 키가 있어야 한다. 기본은 거부다 | 401 `unauthorized` | NFR-SEC-01 |
| BR-51 | 상태 확인은 명시적으로 공개이며 할 일 데이터를 반환하지 않는다 | - | FR-06 |
| BR-52 | 인증 검사는 입력 검증과 업무 규칙보다 먼저 수행한다. 인증되지 않은 호출자에게는 자원의 존재 여부나 검증 결과를 알려 주지 않는다 | 401 `unauthorized` | NFR-SEC-01 |
| BR-53 | 요청 제한을 초과하면 거부한다 (한도는 NFR 단계에서 확정) | 429 `rate_limited` | NFR-SEC-10 |

## 7. 오류 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| BR-60 | 모든 오류 응답은 같은 JSON 구조를 사용한다 (business-logic-model.md 4장) | FR 공통 |
| BR-61 | 검증 오류는 어떤 필드가 왜 잘못되었는지를 담는다. 여러 문제가 있으면 모두 담는다 | FD-CQ1:B |
| BR-62 | 예상하지 못한 오류는 500 `internal_error`와 일반적인 메시지만 반환한다. 스택 트레이스, 파일 경로, SQL, DB 세부 정보는 응답에 넣지 않는다 | NFR-SEC-08 |
| BR-63 | 오류가 나면 동작은 수행되지 않은 것으로 끝난다 (부분 반영 없음) | NFR-SEC-09 |

### 오류 코드 목록

| HTTP | code | 상황 |
|---|---|---|
| 400 | `validation_error` | 본문/쿼리 검증 실패, 정의되지 않은 필드 |
| 401 | `unauthorized` | API 키 없음 또는 불일치 |
| 404 | `not_found` | 대상 항목 없음, 삭제된 항목, 정의되지 않은 경로 |
| 405 | `method_not_allowed` | 경로가 지원하지 않는 메서드 |
| 409 | `duplicate_title` | 같은 제목의 활성 항목 존재 |
| 413 | `payload_too_large` | 본문 크기 상한 초과 |
| 415 | `unsupported_media_type` | 본문이 JSON 콘텐츠 타입이 아님 |
| 429 | `rate_limited` | 요청 제한 초과 |
| 500 | `internal_error` | 예상하지 못한 오류 |
| 503 | `service_unavailable` | 상태 확인에서 저장소 접근 실패 |

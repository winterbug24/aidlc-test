서버, 화면, 기존 API 모듈은 고치지 않았다. 새 의존성은 없다.

## 2. 동작

1. 실행 중인 프로세스 목록을 읽는다.
2. 그중 종료 대상을 고른다. 세 조건을 모두 만족해야 한다.
   - 현재 사용자의 프로세스다
   - 작업 폴더가 이 프로젝트 폴더와 정확히 같다
   - 실행 인자에 `-m`과 `todo_api.server`가 연속된 두 인자로 있다
3. 대상이 없으면 "실행 중인 서버가 없습니다."라고 알리고 끝낸다.
4. 대상에 정상 종료를 요청하고 최대 5초 기다린다. 남아 있으면 강제로 끝내고 1초 더 확인한다.
5. 끈 개수를 알린다. 끄지 못한 것이 있으면 프로세스 번호와 함께 알리고 실패로 끝낸다.

API 키 파일은 읽지 않는다.

## 4. 검증 결과

| 항목 | 결과 |
|---|---|
| 전체 테스트 | 324개 통과 (기존 298개 + 새 26개), 약 59초 |
| 실행 로직 테스트 반복 | 63개를 3회 연속 실행해 모두 통과 |
| 의존성 취약점 스캔 | 알려진 취약점 없음 |
| `todo-stop.bat` 실제 실행 (서버 실행 중) | Windows 명령 해석기로 실행. "서버 1개를 종료했습니다." 출력, 서버 프로세스와 그것을 띄운 실행 로직이 모두 끝났고 화면 주소가 응답하지 않음 |
| `todo-stop.bat` 실제 실행 (서버 없음) | "실행 중인 서버가 없습니다." 출력 |
| 자동 테스트 중 사용자의 서버 | 테스트가 도는 동안 실행 중이던 실제 서버(8000번)는 꺼지지 않았음을 확인 |

### 확인하지 못한 것
- 탐색기에서 `todo-stop.bat`과 바탕화면 바로 가기를 더블클릭하는 동작
- 시작 창에 "서버가 종료되었습니다."가 실제로 표시되는지. 확인 때 끈 서버는 이 안내를 추가하기 전의 코드로 떠 있던 것이라 문구가 나오지 않았다. 문구 자체는 자동 테스트로 확인했다
- 강제 종료 경로(정상 종료에 응답하지 않는 서버)의 실제 동작. 가짜 프로세스로만 테스트했다

### 확인 과정에서 생긴 부수 효과
- 배치 파일 확인을 위해 실행 중이던 서버를 실제로 껐다. 확인 뒤 같은 포트(8000)로 다시 띄웠다

## 5. 생성 중 고친 문제
- 실제 서버를 끄는 테스트가 처음에 실패했다. 프로세스가 끝난 직후 포트 정리가 잠깐 늦어 "포트가 닫혔는지" 확인이 너무 일찍 실행된 것이 원인이었다. 종료 로직의 문제가 아니라 테스트의 타이밍 문제여서, 최대 3초까지 기다려 확인하도록 테스트를 고쳤다

## 6. 요구사항 문서의 제안 대비
요구사항 문서의 "제안하는 결정" 7건을 그대로 구현했다. 달라진 점은 없다.
알아 둘 제약: 프로젝트 폴더가 아닌 곳을 작업 폴더로 해서 띄운 서버는 종료 대상이 아니다. README의 "실행" 절대로 프로젝트 폴더에서 띄운 서버와 시작 파일로 띄운 서버는 모두 대상이다.

## 7. 확장 규칙 준수 요약 (Code Generation 단계)

1차와 2차의 판정에서 달라지는 규칙은 없다. 이번 변경과 관련된 규칙만 적는다.

| 규칙 | 상태 | 근거 |
|---|---|---|
| SECURITY-12 | 준수 | 종료 기능은 키 파일을 읽지 않고 키를 출력하지 않는다 (테스트로 확인) |

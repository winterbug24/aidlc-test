# 기술 스택 결정 - web-ui

1차의 결정(`aidlc-docs/construction/todo-api/nfr-requirements/tech-stack-decisions.md`)은 그대로 유지한다. 실행 의존성(`requirements.txt`)은 바뀌지 않는다.
버전은 2026-10-12에 PyPI에서 확인했다. 하위 의존성을 포함한 정확한 고정 버전은 Code Generation에서 실제 설치 결과로 기록한다.

## 4. 테스트 의존성 (추가)

| 라이브러리 | 버전 | 용도 | 근거 |
|---|---|---|---|
| playwright | 1.63.x (확인 버전 1.63.0) | 브라우저 자동화 | Q11:B |
| pytest-playwright | 0.10.x (확인 버전 0.10.0) | pytest 연동 (브라우저와 페이지 픽스처) | 기존 테스트 러너와 통합 |

- 테스트용 브라우저: Playwright의 Chromium, 화면 없는 모드 (WNFR-Q2:A)
- 브라우저 설치: `python -m playwright install chromium`. 사용자 홈의 캐시 디렉터리에 내려받는다
- WSL 시스템 라이브러리: `libnss3`, `libnspr4`, `libasound2t64`가 필요하다. 2026-10-12에 사용자가 설치했고 설치된 것을 확인했다
- 기존 pytest 9.1.1, Hypothesis 6.169.0, pip-audit 2.10.1은 그대로 쓴다

### Python용 Playwright를 고른 이유
- 기존 테스트가 pytest라 러너, 픽스처, CI 단계를 하나로 유지할 수 있다
- Node.js를 들이지 않는다는 결정(Q2:A)과 맞는다
- 테스트에서 Python으로 서버를 띄우고 DB에 직접 준비 데이터를 넣을 수 있다

## 5. CI 변경

| 항목 | 결정 | 근거 |
|---|---|---|
| 도구 | GitHub Actions 유지 (기존 워크플로에 단계 추가) | 1차의 사용자 결정 |
| 브라우저 설치 | 의존성 설치 뒤에 Chromium과 시스템 라이브러리를 설치하는 단계 추가 | WTST-04 |
| 실행 | 기존 pytest 단계가 브라우저 테스트까지 함께 실행 | 단계 최소화 |
| 실패 분석 | 브라우저 테스트 실패 시 추적 자료를 워크플로 산출물로 보관 | WTST-12 |
| 액션 고정 | 새로 쓰는 액션도 커밋 SHA로 고정 | SECURITY-10 |

CI 실행 시간은 브라우저 내려받기와 테스트로 늘어난다 (1차는 약 30초).

## 6. 검토한 대안

| 주제 | 선택하지 않은 대안 | 이유 |
|---|---|---|
| 화면 기술 | React, Vue + 빌드 도구 | 사용자 선택. 한 페이지 규모에 과하고 Node.js와 공급망이 늘어남 |
| 화면 기술 | 서버 템플릿 렌더링 | 사용자 선택. 동작마다 페이지를 다시 불러와야 함 |
| 키 보관 | 탭 단위 저장, 서버 로그인 쿠키 | 사용자 선택(Q1:B) |
| 화면 제공 | Flask 기본 정적 파일 경로 | 디렉터리 전체가 열리므로, 정해진 파일만 주는 라우트가 더 좁고 명확함 |
| 브라우저 테스트 | Selenium | 드라이버 관리가 따로 필요하고 자동 대기 기능이 약함 |
| 브라우저 테스트 | Node.js용 Playwright | Node.js 도입이 필요하고 테스트 러너가 둘로 나뉨 |
| 대상 브라우저 | 실제 Chrome과 Edge 두 가지 | 사용자 선택(WNFR-Q2:A). 엔진이 같아 얻는 것이 적음 |
| JavaScript 속성 기반 테스트 | fast-check | Node.js가 필요하고 대상 로직이 없음 |
| 실행 파일 | PowerShell 스크립트 | 실행 정책 때문에 더블클릭 실행이 막힐 수 있음 |
| 실행 파일 로직 | 배치 파일 안에 전부 작성 | 테스트하기 어렵고 포트 판정 같은 로직을 배치 문법으로 쓰기 까다로움 |

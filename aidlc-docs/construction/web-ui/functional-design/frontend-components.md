# 프런트엔드 컴포넌트 - web-ui

화면은 한 페이지다. 빌드 도구 없이 순수 HTML, CSS, JavaScript로 만든다.
파일 구성과 이름은 Code Generation 계획에서 확정한다. 여기서 "컴포넌트"는 화면의 논리적 영역과 그것을 다루는 코드 단위를 뜻한다.

## 1. 컴포넌트 계층

```text
Page (/api_test)
+-- Header              제목 "할 일"
+-- Notice              안내 영역 (오류, 정보)
+-- KeyView             화면 모드가 key일 때만 보임
|   +-- KeyForm         키 입력 칸, 확인 버튼
+-- ListView            화면 모드가 list일 때만 보임
|   +-- AddForm         제목 입력 칸, 추가 버튼
|   +-- Toolbar
|   |   +-- FilterTabs  전체 / 미완료 / 완료
|   |   +-- RefreshButton
|   |   +-- ClearKeyButton
|   +-- LoadingIndicator
|   +-- TodoList
|   |   +-- TodoItem    체크 표시, 제목, 삭제 버튼 (항목마다)
|   +-- EmptyState      목록이 비었을 때
+-- ConfirmDialog       삭제 확인 창 (필요할 때만 열림)

화면 밖 코드 단위
+-- AppState            화면 상태 보관과 화면 갱신
+-- ApiClient           API 호출, 제한 시간, 응답 해석
+-- KeyStore            브라우저 저장소의 키 읽기, 쓰기, 지우기
```

## 2. 컴포넌트별 정의

### Notice (안내 영역)
- **입력**: 안내(종류, 문구) 또는 없음
- **표시**: 없으면 영역을 숨긴다. 있으면 종류에 따라 "오류" 또는 "안내"라는 글자 표지와 색을 함께 쓴다
- **동작**: 닫기 버튼을 누르면 안내를 지운다
- **접근성**: 새 안내가 나타나면 화면 낭독기가 읽는다. 오류는 즉시, 정보는 차분하게 알린다
- **규칙**: WR-70~72

### KeyForm (키 입력)
- **상태**: 입력값, 제출 중 여부
- **요소**: 이름표 "API 키", 가려지는 입력 칸, "확인" 버튼, 짧은 설명("서버의 API 키를 붙여넣으세요. 이 브라우저에 저장됩니다")
- **동작**: 확인 버튼 또는 Enter로 제출. 제출 중에는 버튼을 비활성화한다
- **검증**: 앞뒤 공백 제거 후 비어 있으면 제출하지 않음 (WR-10, 11)
- **호출 API**: `GET /todos`
- **결과 처리**: 로직 모델 1.2

### AddForm (할 일 추가)
- **상태**: 입력값, 제출 중 여부
- **요소**: 화면 낭독기용 이름표 "새 할 일", 입력 칸(안내 글 "할 일을 입력하세요", 최대 200자), "추가" 버튼
- **동작**: 추가 버튼 또는 Enter로 제출. 성공하면 입력 칸을 비우고 포커스를 다시 둔다
- **검증**: 200자 제한(입력 단계), 공백만이면 제출하지 않음 (WR-30, 31)
- **호출 API**: `POST /todos`
- **결과 처리**: 로직 모델 1.5

### FilterTabs (필터)
- **입력**: 현재 필터
- **요소**: "전체", "미완료", "완료" 세 버튼. 현재 선택된 것을 모양과 상태 속성 둘 다로 표시한다
- **동작**: 누르면 필터를 바꾸고 목록을 다시 불러온다. 이미 선택된 것을 누르면 아무 일도 하지 않는다
- **호출 API**: `GET /todos` (필터에 따라 `completed` 쿼리)

### RefreshButton (새로고침)
- **동작**: 현재 필터로 목록을 다시 불러온다. 불러오는 중에는 비활성화한다
- **호출 API**: `GET /todos`

### ClearKeyButton (키 지우기)
- **동작**: 저장된 키를 지우고 키 입력 화면으로 간다. 확인을 묻지 않는다 (키는 다시 입력하면 되므로)
- **호출 API**: 없음

### LoadingIndicator (불러오는 중)
- **입력**: 불러오는 중 여부
- **표시**: 참이면 "불러오는 중..." 문구를 보여 준다. 화면 낭독기에도 알린다

### TodoList, TodoItem (목록과 항목)
- **입력**: 목록, 처리 중인 항목
- **TodoItem 요소**: 체크 상자, 제목, 삭제 버튼
  - 체크 상자의 이름표는 제목이다 (제목을 눌러도 체크된다)
  - 삭제 버튼의 화면 낭독기용 이름은 "삭제: <제목>"이다
  - 제목은 텍스트로만 넣는다 (UI-INV-06)
- **표시**: 완료 항목은 취소선과 흐린 색. 긴 제목은 단어 중간에서도 줄바꿈해 넘치지 않게 한다
- **동작**: 체크 상자 변경은 로직 모델 1.6, 삭제 버튼은 1.7. 처리 중인 항목은 체크 상자와 삭제 버튼을 비활성화한다
- **호출 API**: `PATCH /todos/<id>`, `DELETE /todos/<id>`

### EmptyState (빈 목록)
- **표시**: 목록이 비어 있고 불러오는 중이 아닐 때. 전체 필터면 "할 일이 없습니다. 위에서 추가해 보세요", 다른 필터면 "해당하는 할 일이 없습니다" (WR-24)

### ConfirmDialog (삭제 확인 창)
- **입력**: 삭제 대기 항목
- **요소**: 제목 "할 일 삭제", 본문에 대상 제목(텍스트)과 "삭제하면 되돌릴 수 없습니다", "취소" 버튼, "삭제" 버튼
- **동작**: 열릴 때 "취소"에 포커스. 열려 있는 동안 포커스는 창 안에 머문다. Esc와 바깥 클릭은 취소. 닫히면 포커스를 원래 자리로 돌려준다
- **구현 방향**: 브라우저의 기본 대화 상자 요소를 사용해 포커스 가두기와 Esc 처리를 브라우저에 맡긴다
- **규칙**: WR-50~53

### AppState, ApiClient, KeyStore
- **AppState**: `domain-entities.md` 1.2의 값을 보관하고, 값이 바뀌면 해당 영역을 다시 그린다. 화면 모드 전환과 UI-INV-01~04를 책임진다
- **ApiClient**: 모든 호출에 `X-API-Key` 헤더와 제한 시간을 적용하고, 응답을 "성공(데이터)" 또는 "실패(상태 코드, 서버 문구, Retry-After)" 또는 "연결 실패"로 정리해 돌려준다. 응답 처리 규칙(WR-60~67)의 분류를 담당한다
- **KeyStore**: 브라우저 저장소에서 키를 읽고, 쓰고, 지운다. 저장소를 쓸 수 없는 환경(차단 설정 등)에서는 오류를 내지 않고 "이 브라우저에서는 키를 저장할 수 없어 탭을 닫으면 다시 입력해야 합니다"라고 안내한 뒤 메모리에만 보관한다

## 3. 사용자 상호작용 흐름

### 처음 사용
```text
화면 열기 -> KeyView 표시 -> 키 붙여넣기 -> Enter
  -> (성공) ListView 표시, 목록 보임
  -> (실패) Notice에 이유 표시, KeyView 유지
```

### 일상 사용
```text
화면 열기 -> (저장된 키) ListView 바로 표시
  -> AddForm에 입력, Enter -> 목록 맨 위에 추가
  -> TodoItem 체크 -> 완료 표시
  -> FilterTabs "미완료" -> 미완료만 표시
  -> TodoItem 삭제 -> ConfirmDialog -> 삭제 -> 목록에서 사라짐
```

### 문제 상황
```text
어떤 동작 -> 실패 -> Notice에 원인과 조치 표시, 기존 목록 유지
  -> (401) KeyView로 이동, 키 다시 입력
  -> (연결 실패) 서버 확인 후 RefreshButton
```

## 4. 입력 검증 요약

| 입력 | 화면에서 검증 | 서버에 맡김 |
|---|---|---|
| API 키 | 앞뒤 공백 제거, 빈 값 거부 | 올바른 키인지 |
| 할 일 제목 | 200자 제한, 공백만인 값 거부 | 제어 문자, 중복, 그 밖의 모든 규칙 |

화면의 검증은 편의를 위한 것이고, 최종 판단은 항상 서버가 한다.

## 5. 표시 규칙 (US-14)

| 항목 | 규칙 |
|---|---|
| 배치 | 가운데 정렬된 한 단. 본문 최대 너비를 두어 넓은 창에서도 줄이 너무 길어지지 않게 한다 |
| 좁은 창 | 약 480px까지 가로 스크롤 없이 표시. Toolbar의 버튼은 필요하면 다음 줄로 넘어간다 |
| 글꼴 | Windows 기본 글꼴(Segoe UI, 맑은 고딕) 우선. 웹 글꼴을 내려받지 않는다 |
| 테마 | 시스템의 밝게/어둡게 설정에 따라 색 묶음을 바꾼다. 입력 칸, 버튼, 확인 창, 스크롤 막대도 테마를 따른다 |
| 대비 | 본문 글자와 배경, 흐린 글자(완료 항목)와 배경 모두 읽기에 충분한 대비를 갖는다 (기준 수치는 NFR 단계) |
| 포커스 | 키보드 포커스가 있는 요소에 뚜렷한 테두리를 보여 준다 |
| 화면 배율 | 크기를 글자 크기에 비례하는 단위로 잡아 125%, 150% 배율에서도 깨지지 않게 한다 |
| 장식 | 그림자, 애니메이션, 아이콘 글꼴을 쓰지 않거나 최소화한다. 움직임 줄이기 설정을 따른다 |
| 키보드 순서 | 화면에 보이는 순서대로: (KeyView) 키 입력 칸, 확인 / (ListView) 제목 입력 칸, 추가, 필터 세 개, 새로고침, 키 지우기, 항목별 체크 상자와 삭제 |

## 6. 테스트용 식별자 (`data-testid`)

값은 `{컴포넌트}-{역할}` 형식이며 화면이 바뀌어도 유지한다.

| 요소 | data-testid |
|---|---|
| 안내 영역 | `notice` |
| 안내 문구 | `notice-message` |
| 안내 닫기 버튼 | `notice-close-button` |
| 키 입력 화면 영역 | `key-view` |
| 키 입력 칸 | `key-form-input` |
| 키 확인 버튼 | `key-form-submit-button` |
| 목록 화면 영역 | `list-view` |
| 제목 입력 칸 | `add-form-input` |
| 추가 버튼 | `add-form-submit-button` |
| 필터 전체 | `filter-all-button` |
| 필터 미완료 | `filter-pending-button` |
| 필터 완료 | `filter-completed-button` |
| 새로고침 버튼 | `refresh-button` |
| 키 지우기 버튼 | `clear-key-button` |
| 불러오는 중 표시 | `loading-indicator` |
| 목록 | `todo-list` |
| 항목 (줄) | `todo-item` (할 일 id는 `data-todo-id` 속성으로 따로 둔다) |
| 항목 체크 상자 | `todo-item-checkbox` |
| 항목 제목 | `todo-item-title` |
| 항목 삭제 버튼 | `todo-item-delete-button` |
| 빈 목록 안내 | `empty-state` |
| 삭제 확인 창 | `confirm-dialog` |
| 확인 창의 대상 제목 | `confirm-dialog-title` |
| 확인 창 취소 버튼 | `confirm-dialog-cancel-button` |
| 확인 창 삭제 버튼 | `confirm-dialog-confirm-button` |

항목 안의 요소는 값이 같으므로, 테스트는 항목(줄)을 먼저 찾고 그 안에서 요소를 찾는다.

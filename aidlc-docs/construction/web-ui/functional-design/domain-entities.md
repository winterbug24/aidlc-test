# 도메인 엔티티 - web-ui

서버의 `Todo` 엔티티와 DB는 바뀌지 않는다 (`aidlc-docs/construction/todo-api/functional-design/domain-entities.md`).
이 문서는 화면과 실행 파일이 다루는 상태를 정의한다.

## 1. 화면 상태

### 1.1 화면 모드 (View)

| 값 | 의미 | 보이는 것 |
|---|---|---|
| `starting` | 화면을 막 열어 저장된 키를 확인하는 중 | 불러오는 중 표시 |
| `key` | 키 입력 화면 | 키 입력 양식, 안내 영역 |
| `list` | 할 일 목록 화면 | 추가 양식, 필터, 새로고침, 키 지우기, 목록, 안내 영역 |

### 1.2 화면이 기억하는 값

| 이름 | 타입 | 초기값 | 설명 |
|---|---|---|---|
| 저장된 키 (StoredKey) | 문자열 또는 없음 | 브라우저 저장소의 값 | 브라우저 저장소에 보관. 주소(포트 포함)마다 따로 저장됨 |
| 필터 (Filter) | `all`, `pending`, `completed` | `all` | 화면을 열 때마다 `all`로 시작. 저장하지 않음 |
| 목록 (Todos) | Todo 표현의 배열 | 빈 배열 | 현재 필터에 해당하는 항목. 서버가 준 순서(최신 순) 그대로 |
| 안내 (Notice) | 종류(`error`, `info`)와 문구, 또는 없음 | 없음 | 화면 위쪽 안내 영역에 표시할 내용. 한 번에 하나 |
| 불러오는 중 (Loading) | 불리언 | 거짓 | 목록을 불러오는 요청이 진행 중인지 |
| 삭제 대기 항목 (PendingDelete) | Todo 표현 또는 없음 | 없음 | 삭제 확인 창이 열려 있는 대상 |
| 처리 중인 항목 (BusyIds) | id의 집합 | 빈 집합 | 완료 변경이나 삭제 요청이 진행 중인 항목. 같은 항목의 중복 요청을 막는다 |

화면이 쓰는 Todo 표현은 API가 주는 것과 같다: `id`, `title`, `completed`, `created_at`.

### 1.3 화면 모드 전환

```text
                +------------+
   open page -> |  starting  |
                +------------+
                  |        |
     no stored key|        |stored key, list request sent
                  v        v
            +---------+   200    +---------+
            |   key   | -------> |  list   |
            |         | <------- |         |
            +---------+   401    +---------+
                 ^      or clear key   |
                 |                     |
                 +---------------------+
```

#### 텍스트 설명
- 화면을 열면 `starting`에서 시작한다.
- 저장된 키가 없으면 `key`로 간다.
- 저장된 키가 있으면 목록을 요청하고, 200이면 `list`로, 401이면 키를 지우고 `key`로 간다. 그 밖의 실패(요청 제한, 연결 실패, 서버 오류)는 `list`로 가서 빈 목록과 안내를 보여 주고 다시 시도할 수 있게 한다.
- `key`에서 올바른 키를 내면 `list`로 간다.
- `list`에서 "키 지우기"를 누르거나 어떤 요청이 401을 받으면 `key`로 간다.

### 1.4 화면 상태의 불변 조건

| ID | 불변 조건 |
|---|---|
| UI-INV-01 | `key` 모드에서는 할 일 목록이 화면에 없다 (목록 데이터도 비운다) |
| UI-INV-02 | 저장된 키는 서버가 받아들인(목록 조회 200) 키뿐이다 |
| UI-INV-03 | 목록의 모든 항목은 현재 필터에 해당한다 |
| UI-INV-04 | 안내는 한 번에 하나만 보인다. 새 안내는 이전 안내를 대체한다 |
| UI-INV-05 | API 키는 주소(URL), 화면의 보이는 글자, 콘솔 출력 어디에도 나타나지 않는다 |
| UI-INV-06 | 서버에서 온 문자열(제목, 오류 문구)은 텍스트로만 화면에 들어간다 |

## 2. 실행 파일이 다루는 상태

| 이름 | 위치 | 설명 |
|---|---|---|
| 키 파일 | 프로젝트 루트의 `.env` | `TODO_API_KEY=<값>` 한 줄. 소유자 전용 권한, 버전 관리 제외. 없으면 실행 파일이 만든다 |
| 후보 포트 | 8000~8009 | 서버를 띄울 수 있는 포트 범위. 낮은 번호가 우선 |
| 포트 상태 | 실행 시점에 판정 | 포트마다 `ours`(이 To-Do 서버가 응답), `busy`(다른 프로그램이 사용 중), `free`(비어 있음) 중 하나 |
| 선택 결과 | 실행 시점에 결정 | `reuse(포트)`(이미 실행 중인 서버 사용), `start(포트)`(새로 시작), `none`(빈 포트 없음) 중 하나 |

### 포트 상태 판정 기준

| 상태 | 기준 |
|---|---|
| `ours` | 그 포트의 `/todos`를 키 파일의 키로 호출하면 200이 온다 |
| `busy` | `ours`가 아니고, Windows 쪽 또는 WSL 쪽 어느 한쪽에서라도 그 포트를 쓰는 프로그램이 있다 |
| `free` | Windows 쪽과 WSL 쪽 모두에서 비어 있다 |

브라우저는 Windows에서 실행되므로, Windows 프로그램이 쓰는 포트는 WSL 안에서 비어 보여도 쓸 수 없다. 그래서 두 쪽을 모두 확인한다.

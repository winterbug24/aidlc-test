# 업무 규칙 - web-ui

근거 표기: US/AC는 사용자 스토리, WFR/WNFR은 요구사항, FD-Q는 이 단계의 설계 질문을 가리킨다.
기존 API의 규칙(BR-xx)은 `aidlc-docs/construction/todo-api/functional-design/business-rules.md`에 있으며 바뀌지 않는다.

## 1. 화면 제공 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| WR-01 | 화면은 `GET /api_test`로 제공한다. 화면에 필요한 스타일과 스크립트는 `/api_test` 아래 경로로 제공한다 | WFR-01 |
| WR-02 | 화면 파일은 인증 없이 제공한다. 화면 파일에는 할 일 데이터와 API 키가 없다 | WFR-01, WNFR-SEC-04 |
| WR-03 | 화면 제공 경로는 미리 정해 둔 화면 파일만 돌려준다. 그 밖의 경로는 404다 | WNFR-SEC-09 |
| WR-04 | 화면은 외부 출처의 자원을 불러오지 않는다 | WNFR-SEC-02 |
| WR-05 | 화면을 처음 여는 데 드는 요청은 화면 문서 1, 스타일 1, 스크립트 1, 목록 조회 1로 모두 4회다. 브라우저가 따로 아이콘을 요청하지 않게 한다 | WNFR-PERF-01 |

## 2. 키 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| WR-10 | 입력한 키는 앞뒤 공백과 줄바꿈을 제거한 뒤 사용한다 (붙여넣기 대비) | US-05 |
| WR-11 | 빈 키는 서버에 보내지 않고 키를 입력하라고 안내한다 | US-05 |
| WR-12 | 키 검증은 그 키로 목록을 조회해서 한다. 200이면 키를 저장하고 그 응답을 첫 목록으로 쓴다 | AC-05.3, WNFR-PERF-02 |
| WR-13 | 키 검증이 401이면 저장하지 않고 "API 키가 올바르지 않습니다"라고 안내한다 | AC-15.1 |
| WR-14 | 키 검증이 429면 저장하지 않고 요청 제한 안내(WR-43)를 한다. 키가 틀렸다는 안내와 문구가 다르다 | AC-17.2 |
| WR-15 | 키는 `X-API-Key` 요청 헤더로만 보낸다. 주소에 넣지 않고 콘솔에 출력하지 않는다 | WNFR-SEC-05 |
| WR-16 | 키 입력 칸은 입력 내용을 가린다. 브라우저의 자동 완성 저장 대상이 되지 않게 한다 | AC-05.2 |
| WR-17 | "키 지우기"는 확인 없이 즉시 저장된 키와 화면의 목록 데이터를 지우고 키 입력 화면으로 간다 | US-07 |
| WR-18 | 저장된 키로 보낸 요청이 401을 받으면 저장된 키와 목록 데이터를 지우고, "API 키가 올바르지 않거나 바뀌었습니다. 다시 입력해 주세요"라는 안내와 함께 키 입력 화면으로 간다 | AC-15.2 |

## 3. 목록과 필터 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| WR-20 | 목록은 서버가 준 순서 그대로 보여 준다 (최신 순). 화면에서 다시 정렬하지 않는다 | AC-08.1 |
| WR-21 | 필터는 서버에 맡긴다: 전체는 쿼리 없음, 미완료는 `completed=false`, 완료는 `completed=true` | US-12 |
| WR-22 | 목록을 서버에서 불러오는 때는 다음뿐이다: 화면을 열 때(저장된 키가 있으면), 키 검증에 성공할 때, 필터를 바꿀 때, 새로고침을 누를 때 | WFR-08, AC-13.2 |
| WR-23 | 완료 항목은 체크된 상태, 취소선, 흐린 색으로 표시한다. 순서는 바꾸지 않는다 | AC-08.2 |
| WR-24 | 목록이 비면 안내를 보여 준다. 전체 필터에서는 "할 일이 없습니다", 다른 필터에서는 "해당하는 할 일이 없습니다" | AC-08.3, AC-12.5 |
| WR-25 | 목록을 불러오는 동안 불러오는 중 표시를 한다. 요청이 끝나면(성공, 실패, 제한 시간 초과 모두) 표시를 없앤다 | AC-08.6, AC-18.2 |
| WR-26 | 목록 요청이 실패하면 화면에 있던 목록을 그대로 둔다 | AC-17.1, AC-18.1 |
| WR-27 | 먼저 보낸 목록 요청의 응답이 나중에 보낸 요청의 응답보다 늦게 오면 버린다 (필터를 빠르게 바꿀 때 엉뚱한 목록이 보이지 않게) | UI-INV-03 |

## 4. 추가 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| WR-30 | 입력 칸은 200자까지만 입력된다 | AC-09.4 |
| WR-31 | 앞뒤 공백을 제거했을 때 빈 제목이면 서버에 보내지 않고 "제목을 입력해 주세요"라고 안내한다 | AC-09.3 |
| WR-32 | 그 밖의 검증(제어 문자, 중복 등)은 서버에 맡기고 서버의 안내 문구를 보여 준다 | AC-16.1, AC-16.2 |
| WR-33 | 추가는 서버 응답(201)을 받은 뒤 화면에 반영한다. 응답의 할 일을 목록 맨 위에 넣고 입력 칸을 비운 뒤 입력 칸에 포커스를 둔다 | AC-09.1 |
| WR-34 | 현재 필터가 "완료"면 새 할 일(미완료)은 목록에 넣지 않고 "추가했습니다. 현재 필터에서는 보이지 않습니다"라고 알린다 | UI-INV-03 |
| WR-35 | 추가가 실패하면 입력 칸의 내용을 지우지 않는다 | AC-16.1 |
| WR-36 | 추가 요청이 진행 중일 때는 다시 추가할 수 없다 (중복 제출 방지) | - |

## 5. 완료 체크 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| WR-40 | 체크 표시를 누르면 화면에 즉시 반영하고 서버에 변경을 요청한다 | US-10 |
| WR-41 | 요청이 실패하면 체크 표시를 원래대로 되돌리고 안내한다 | AC-10.3 |
| WR-42 | 요청이 성공했고 바뀐 상태가 현재 필터에 해당하지 않으면 그 항목을 목록에서 뺀다 | AC-12.4 |
| WR-44 | 같은 항목에 대한 요청이 진행 중이면 그 항목의 체크와 삭제를 받지 않는다 | - |

## 6. 삭제 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| WR-50 | 삭제 버튼을 누르면 화면 가운데에 확인 창을 띄운다. 확인 창에는 대상 제목과 "삭제하면 되돌릴 수 없습니다"라는 문구가 있다 | AC-11.1, FD-Q2:B |
| WR-51 | 확인 창이 열릴 때 포커스는 "취소"에 둔다. Esc 키와 창 바깥 영역 클릭은 취소다 | AC-11.3 |
| WR-52 | "삭제"를 누르면 서버에 삭제를 요청하고, 성공(204)하면 목록에서 뺀다 | AC-11.2 |
| WR-53 | 확인 창이 닫히면 포커스를 원래 있던 곳 근처로 돌려준다 | WNFR-UX-05 |

## 7. 응답 처리 규칙

모든 API 호출에 공통으로 적용한다.

| ID | 상황 | 처리 | 근거 |
|---|---|---|---|
| WR-60 | 성공 (2xx) | 동작을 반영하고 이전 안내를 지운다 | AC-16.3 |
| WR-61 | 401 | WR-18 (키 검증 중이면 WR-13) | US-15 |
| WR-62 | 400, 409, 413, 415 | 서버의 `error.message`를 오류 안내로 보여 준다 | AC-16.1, AC-16.2 |
| WR-63 | 404 (완료 변경, 삭제에서) | "이미 삭제된 할 일입니다"라고 안내하고 그 항목을 목록에서 뺀다 | - |
| WR-43 | 429 | 서버의 `error.message`를 보여 준다. `Retry-After` 헤더가 있으면 "약 N초 후"를 덧붙인다 | US-17 |
| WR-64 | 500, 503 등 5xx | 서버의 `error.message`를 보여 주고 다시 시도할 수 있음을 알린다 | AC-18.3 |
| WR-65 | 연결 실패 또는 제한 시간 초과 | "서버에 연결할 수 없습니다. 서버가 실행 중인지 확인한 뒤 새로고침을 눌러 주세요"라고 안내한다 | AC-18.1, AC-18.2 |
| WR-66 | 응답 본문을 해석할 수 없음 (JSON이 아님 등) | "예상하지 못한 응답입니다 (상태 코드 N)"라고 안내한다 | WFR-09 |
| WR-67 | 모든 API 호출에 제한 시간을 둔다 (값은 NFR 단계에서 확정) | - | WNFR-RES-02 |
| WR-68 | 어떤 실패도 화면을 빈 화면이나 조작 불가 상태로 만들지 않는다 | - | WFR-09 |

## 8. 안내 영역 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| WR-70 | 안내는 화면 위쪽의 고정된 영역에 보여 준다. 오류와 정보 안내를 색과 문구로 구분한다 (색만으로 구분하지 않는다) | FD-Q1:A |
| WR-71 | 안내는 닫기 버튼을 누르거나 다음 동작이 성공할 때까지 남아 있다 | FD-Q1:A |
| WR-72 | 새 안내가 나타나면 화면 낭독기가 읽을 수 있게 알린다 | WNFR-UX-05 |

## 9. 실행 파일 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| WR-80 | 실행 파일은 프로젝트 폴더에 두고 쓴다. 자기 위치에서 WSL 배포판 이름과 프로젝트 경로를 알아낸다. WSL 경로가 아닌 곳에서 실행되면 "프로젝트 폴더에 두고 바로 가기로 실행하세요"라고 안내하고 끝낸다 | FD-Q3:A |
| WR-81 | 가상 환경이 없으면 서버를 시작하지 않고 README의 설치 절을 안내한다 | AC-01.4 |
| WR-82 | 키 파일이 없으면 32자 이상의 무작위 키를 만들어 소유자 전용 권한으로 저장하고 클립보드에 복사한다. 키 값은 창에 표시하지 않는다 | AC-01.3 |
| WR-83 | 후보 포트(8000~8009) 전체를 먼저 살펴 `ours`인 포트가 있으면 그 포트의 화면을 열고 끝낸다. 새 서버를 시작하지 않는다 | US-02 |
| WR-84 | `ours`인 포트가 없으면 `free`인 포트 중 가장 낮은 번호로 서버를 시작한다 | US-03 |
| WR-85 | `free`인 포트가 없으면 서버를 시작하지 않고 그 사실을 알린다 | AC-03.3 |
| WR-86 | 서버를 시작한 뒤 서버가 응답할 때까지 기다렸다가 브라우저를 연다. 정해진 시간 안에 응답이 없으면 브라우저를 열지 않고 서버를 정리한 뒤 로그 위치를 안내한다 (대기 시간은 NFR 단계에서 확정) | AC-01.1, AC-01.4 |
| WR-87 | 서버가 뜨면 창에 화면 주소와 "이 창을 닫거나 Ctrl+C를 누르면 서버가 꺼집니다"를 표시한다. 8000번이 아닌 포트면 "이 주소에서는 키를 다시 입력해야 할 수 있습니다. 키 복사 파일을 실행하세요"도 표시한다 | AC-01.2, AC-03.2 |
| WR-88 | 서버는 실행 창이 열려 있는 동안만 동작한다. 창을 닫거나 Ctrl+C를 누르면 서버 프로세스가 끝난다 | FD-Q4:A, AC-04.2 |
| WR-89 | 키 복사 전용 파일은 키 파일의 키를 클립보드에 복사하고 복사했다고 알린 뒤 끝난다. 키 값은 표시하지 않는다. 키 파일이 없으면 시작 파일을 먼저 실행하라고 안내한다 | FD-Q5:A, AC-04.1 |
| WR-90 | 키는 명령줄 인자로 넘기지 않는다 (프로세스 목록에 노출되지 않게). 환경 변수나 권한이 제한된 파일로 넘긴다 | WNFR-SEC-06 |
| WR-91 | 시작 파일은 키를 처음 만들 때만 클립보드에 복사한다. 이미 키가 있으면 클립보드를 건드리지 않는다 | FD-Q5:A |

# 논리 컴포넌트 - web-ui

패턴 번호(WSP, WRP, WPP, WDP, WTP)는 `nfr-design-patterns.md`를 가리킨다.
1차의 컴포넌트(C-01~C-15)는 `aidlc-docs/construction/todo-api/nfr-design/logical-components.md`에 있다.
파일 이름은 방향을 보이기 위한 것이며 Code Generation 계획에서 확정한다.

| C-15 CI 워크플로 | 브라우저 설치 단계와 실패 시 추적 자료 보관 단계 추가 | 브라우저 테스트 |
| 개발 의존성 고정 파일 | playwright, pytest-playwright와 하위 의존성 추가 | 브라우저 테스트 |
| 테스트 공용 파일 (`conftest.py`, `strategies.py`) | 브라우저 테스트 장치와 실행 로직용 제너레이터 추가 | W-09, PBT-07 |

## 3. 의존 관계

```text
C-02 App Factory
  -> W-01 Security Headers            (신규 등록)
  -> W-02 Web Routes -> W-03 Web Assets (신규 등록)
  -> C-08 Todo Routes, C-09 Health Route, 그 밖의 기존 컴포넌트 (변경 없음)

W-03 Web Assets (브라우저에서 실행)
  W-03e Actions -> W-03c AppState -> W-03d Views
  W-03e Actions -> W-03b ApiClient -> W-03a KeyStore
  W-03b ApiClient -> HTTP -> C-08 Todo Routes (기존 API)

W-07 Batch Files -> W-06 Launcher Effects
  W-06 -> W-05 Environment Checks -> W-04 Pure Logic
  W-06 -> C-13 Server Entry (별도 프로세스로 시작)
  W-05 -> HTTP -> C-08 Todo Routes, C-09 Health Route (식별과 응답 확인)
```

의존 규칙:
- 화면 라우트(W-02)는 인증, 저장소, DB에 의존하지 않는다. 파일만 준다
- 화면 스크립트에서 키 값을 다루는 단위는 KeyStore와 ApiClient뿐이다
- 실행 로직의 순수 계산(W-04)은 네트워크, 파일, 프로세스에 의존하지 않는다
- 실행 로직은 앱 팩토리나 Flask를 가져오지 않는다. 서버는 별도 프로세스로만 띄운다

## 4. 요청 처리 파이프라인의 변화

1차의 파이프라인에 두 가지가 달라진다.

```text
요청 수신
  1. 요청 ID 생성, 시작 시각 기록, 본문 크기 확인   (C-11, 변경 없음)
  2. 요청 제한 확인                                 (C-04, 변경 없음. 화면 파일 요청도 대상)
  3. 라우트 분기
     - /todos ...        : 인증 -> 검증 -> 저장소      (변경 없음)
     - /health           : DB 확인                     (변경 없음)
     - /api_test ...     : 고정 목록에서 파일 찾기 -> 파일 응답 또는 404   (신규, 인증 없음)
  4. 응답 후처리
     - 보안 헤더와 캐시 헤더 설정                   (W-01, 신규 컴포넌트로 이동)
     - 요청 ID 헤더, 요청 로그                      (C-11, 변경 없음)
```

## 5. 화면 주소 구성

| 주소 | 내용 | 콘텐츠 유형 |
|---|---|---|
| `GET /api_test` (끝에 `/`가 있어도 같음) | 화면 문서 | `text/html; charset=utf-8` |
| `GET /api_test/app.css` | 스타일 | `text/css; charset=utf-8` |
| `GET /api_test/app.js` | 스크립트 | `text/javascript; charset=utf-8` |
| `GET /api_test/<그 밖의 이름>` | 404 (기존 공통 JSON 오류 형식) | `application/json` |

- 화면 문서는 스타일과 스크립트를 `/api_test/app.css`, `/api_test/app.js`라는 절대 경로로 참조한다
- 화면 스크립트는 API를 `/todos`라는 절대 경로로 호출한다 (같은 출처)
- 루트 `/`는 지금처럼 404다

## 6. 실행 파일 구성

| 파일 | 역할 |
|---|---|
| 시작용 배치 파일 | 더블클릭 진입점. 실행 로직의 "시작" 명령을 호출하고, 끝나면 창이 바로 닫히지 않게 멈춘다 |
| 키 복사용 배치 파일 | 더블클릭 진입점. 실행 로직의 "키 복사" 명령을 호출한다 |
| 실행 로직 모듈 | 판단과 동작 전부. 가상 환경의 Python으로 실행 |

배치 파일이 하는 일은 세 가지뿐이다: 한글 출력을 위한 문자 집합 설정, 자기 위치(`\\wsl.localhost\<배포판>\<경로>` 또는 `\\wsl$\...`)에서 배포판 이름과 리눅스 경로 추출, 그 배포판과 경로로 실행 로직 호출. 위치가 WSL 경로가 아니면 안내하고 끝낸다.

실행 로직이 쓰는 Windows 프로그램 (모두 WSL에서 호출):

| 용도 | 수단 |
|---|---|
| 클립보드 복사 | Windows의 클립보드 명령에 키를 표준 입력으로 전달 |
| 브라우저 열기 | Windows 명령 해석기의 "기본 프로그램으로 열기"에 화면 주소 전달 (주소에는 키가 없음) |
| Windows 쪽 수신 포트 목록 | Windows의 네트워크 상태 명령 출력을 한 번 읽어 후보 포트를 찾음 |

세 프로그램은 Windows 시스템 디렉터리의 절대 경로로 호출한다. 경로 검색 순서에 따라 다른 프로그램이 실행되는 일을 막는다.
